## <span style="color: #27AE60;">WordPress REST APIって何？その力を知ろう</span>



まず、この自動化の根幹となる「WordPress REST API」が一体何者なのか、ここをしっかり理解しておきましょう。難しく考える必要はありません。簡単に言えば、WordPressの中にある「記事」や「カテゴリー」といった様々な情報を、別のプログラム（今回で言えばPythonですね）がインターネット越しに「ちょうだい！」と要求したり、「これを追加して！」と指示したりするための、共通の「言葉」や「窓口」のようなものだと思ってください。

私が初めてREST APIという概念に触れた時も、最初は難しそうに感じたものです。でも、一度その仕組みがわかると、まるで目からウロコでしたね。まるでウェブサイトそのものを遠隔操作するような感覚なんです。Pythonなどのプログラミング言語から、特定のURL（これをエンドポイントと呼びます）にデータを送ったり受け取ったりすることで、手作業でWordPressの管理画面を触るのと同じか、それ以上のことを自動でやってのけられるようになるわけです。例えば、新しい記事を投稿する、既存の記事を更新する、カテゴリーを追加する、といった操作が、全てプログラムでできるようになります。これがまさに「WordPress: PythonでREST API連携！ブログ自動投稿の第一歩」の醍醐味なんですよ。

この「窓口」は、実はWordPressのバージョン2.0から存在しているXML-RPCという機能の進化版として、よりモダンで柔軟な形式としてWordPress 4.7以降で標準搭載されるようになりました。これにより、ウェブサイトの裏側にあるデータを、JSONという形式で構造的にやり取りできるようになっています。私たちはこのJSONデータを使って、PythonからWordPressに命令を出すことで、ブログ運営の多くのルーティン作業から解放される道が開けるんです。データの形式ややり取りのルールが明確になっているので、一度慣れてしまえば、どんな情報でも思い通りに操れるようになりますよ。



## <span style="color: #C0392B;">WordPressの準備を始めよう！API連携の土台作り</span>



PythonからWordPressにアクセスし、記事を自動投稿するためには、WordPress側のいくつかの準備が必要です。ここが疎かになっていると、後で「なぜ動かないんだ！？」と頭を抱えることになりますので、焦らず、しかし丁寧に設定していきましょう。

まず、最も重要なのが「パーマリンク設定」です。WordPressの管理画面から「設定」→「パーマリンク」へと進んでください。ここで「投稿名」や「数字ベース」など、人間が読みやすい形式に設定されていることを確認してください。もし「基本」のようなデフォルトのままになっていると、APIが正しく動作しない場合があります。これは、REST APIが特定のURL構造に基づいて情報をやり取りするため、美しいパーマリンク形式になっていないと、どの「窓口」に話しかければいいのか分からなくなってしまうからです。私たちのプロジェクトで新しいWordPressサイトにAPI連携を導入する際、最初に必ず確認するのがこのパーマリンク設定なんです。もし設定を変えたら、必ず「変更を保存」をクリックしてくださいね。

次に、API連携を行うための「ユーザー」と「認証情報」を用意します。自動投稿用の特別なユーザーを作成することをおすすめします。管理画面の「ユーザー」→「新規追加」から新しいユーザーを作成し、権限グループは少なくとも「投稿者」や「編集者」を選んでください。その上で、最も安全な認証方法として「アプリケーションパスワード」を発行します。作成したユーザーのプロフィール編集画面の一番下までスクロールすると「新しいアプリケーションパスワード」という項目がありますので、ここに任意の名前（例: `python_auto_post`）を入力して「新しいアプリケーションパスワードを追加」ボタンをクリックしてください。すると、一度だけ表示されるパスワードが生成されます。これをPythonスクリプトの中で利用することになるので、必ずコピーして安全な場所に保管しておいてください。このパスワードは、あなたのWordPressサイトへのアクセス権限を持つ、非常に重要な鍵です。紛失したり、不用意に共有したりしないよう、厳重な管理をお願いします。この土台作りこそが、まさに「WordPress: PythonでREST API連携！ブログ自動投稿の第一歩」を成功させるための肝になりますからね。

さあ、WordPress側の土台がしっかりと整ったら、いよいよPythonの出番です。実際にPythonスクリプトからWordPressのREST APIを「叩く」方法を、一つずつ丁寧に見ていきましょう。この段階で「あれ？思ったより簡単だぞ！」と感じていただけたら、もう自動化の扉はすぐそこです。



## <span style="color: #27AE60;"><span style="color: #4CAF50;">PythonでREST APIを叩く！投稿スクリプトの基礎</span></span>



Pythonからウェブ上のAPIと連携する際、ほとんどの場合にお世話になるのが `requests` ライブラリです。これはHTTPリクエストを驚くほど簡単に扱えるようにしてくれる、まさに頼れる相棒。まずは、もしインストールしていなければ、ターミナルやコマンドプロンプトで `pip install requests` と入力して導入しておきましょうね。

ブログ記事を新規投稿するには、WordPress REST APIの「投稿」エンドポイントに対して `POST` メソッドでリクエストを送ります。エンドポイントのURLは、通常あなたのWordPressサイトのURLの末尾に `/wp-json/wp/v2/posts` を追加した形になります。例えば、`https://yourdomain.com/wp-json/wp/v2/posts` のようになるわけです。

ここで、前回用意したアプリケーションパスワードが活躍します。API認証にはHTTP Basic認証を使います。`requests` ライブラリでは、`auth` パラメータに `requests.auth.HTTPBasicAuth(username, application_password)` を渡すだけでOK。`username` はアプリケーションパスワードを発行したユーザーのログイン名、`application_password` は発行された一意の文字列ですよ。

私が初めてPythonからAPIを叩いた時、この `requests` ライブラリのシンプルさに感動しましたね。これなら複雑な認証も難なくクリアできると感じました。しかし、ここで一つ大切な注意点があります。アプリケーションパスワードをスクリプト内に直接書き込むのは、セキュリティ上、非常に危険です。特にチームで開発したり、GitHubなどの公開リポジトリに置いたりする可能性のある場合は、必ず環境変数などを使って外部から安全に読み込むようにしてください。これは、あなたのWordPressサイトの裏口の鍵を、むやみに人目に晒さないための鉄則です。

## <span style="color: #E74C3C;"><span style="color: #E67E22;">投稿データの作り込みとAPI連携の落とし穴</span></span>



さて、先ほどのスクリプトで `post_data` を見て「カテゴリーやタグってIDで指定するの？」と疑問に思った方もいるかもしれません。まさにその通りなんです。WordPress REST APIでは、カテゴリーやタグ、そしてアイキャッチ画像（メディア）といった関連するデータは、そのIDで指定する必要があります。ここが、多くの人が初めてAPI連携をする際に「なぜうまく動かないんだ！」と悩むポイントの一つですね。

例えば、「Python」という名前のカテゴリーに記事を投稿したい場合、まずその「Python」カテゴリーのIDをAPIで取得するか、WordPress管理画面で調べておく必要があります。カテゴリーやタグの一覧は、それぞれ `/wp-json/wp/v2/categories` や `/wp-json/wp/v2/tags` というエンドポイントに `GET` リクエストを送ることで取得できます。一度IDを調べてしまえば、あとはスクリプトに設定するだけなので、この一手間を惜しまないでください。私たちのプロジェクトでも、カテゴリーやタグを動的に扱う際、毎回IDを調べてから送るという処理が必要になり、この部分で多くの人がつまずくのを見てきました。もし存在しないIDを指定してしまった場合、APIはエラーを返したり、単にその指定を無視したりすることがありますから、注意が必要です。

また、アイキャッチ画像の設定は、カテゴリーやタグよりも少し複雑です。WordPressの記事にアイキャッチ画像を設定するには、まずその画像をWordPressのメディアライブラリにアップロードする必要があります。これは `/wp-json/wp/v2/media` エンドポイントに `POST` リクエストを送り、画像ファイルをバイナリデータとして送信することで行います。アップロードが成功すると、APIはその画像のメディアIDを返してくれます。そのメディアIDを、記事投稿時の `post_data` の `featured_media` フィールドに指定することで、初めてアイキャッチ画像が設定される、という流れになります。

**メディアアップロードのポイント:** `requests` でファイルをアップロードする際は、`files` パラメータを使うのが一般的ですが、REST APIでは `Content-Disposition` ヘッダにファイル名を含めるなどの細かい調整が必要になる場合があります。特に `_wp_nonce` が必要な場合もあるので、公式ドキュメントを参考にしながら丁寧に実装を進めることをおすすめします。このメディア周りの連携は、自動投稿の「見た目」を豊かにするためには避けて通れない道ですが、最も実装が複雑になりがちな部分です。もしメディアアップロードでつまずいたら、一度、小さな画像ファイルで単体テストをしてみるのが良いでしょう。

これらの「落とし穴」を事前に知っておくことで、無用なトラブルを避け、スムーズな自動投稿ライフへの第一歩を力強く踏み出せるはずです。焦らず、一つずつ着実に、PythonとWordPressの連携を楽しんでくださいね。
